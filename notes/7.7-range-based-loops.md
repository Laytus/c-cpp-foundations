# Module 7.7 – Range-based Loops

### Learning Goals

- Understand the **range-based for loop** syntax
- Learn how it simplifies iteration over containers
- Understand the difference between **copy**, **reference**, and **const reference**
- Learn when each form should be used
- Understand how range-based loops work internally

---

## The Core Idea

A **range-based loop** iterations directly over the elements of a container.

Example:

```cpp
for (auto x : container) {
    ...
}
```

Meaning:

```txt
for each element in container
    assign element to x
```

This replaces the classic indexed loop.

---
## Classic C++ Loop

Before range-based loops:

```cpp
for (size_t i = 0; i < v.size(); i++) {
    std::cout << v[i];
}
```

Problems:

- index management
- more code
- easy off-by-one errors
- less readable

---

## Range-based Loop

Modern C++:

```cpp
for (auto x : v) {
    std::cout << x;
}
```

Much simpler.

---

## Example with `std::vector`

```cpp
std::vector<int> v = {1,2,3,4};

for (auto x : v) {
    std::cout << x << " ";
}
```

Output:

```
1 2 3 4
```

Each iteration copies the element into `x`.

---

## Copy vs Reference

There are **three common forms**.

#### 1. Copy

```cpp
for (auto x : v)
```

Each iteration copies the element.

Example:

```cpp
for (auto x : v) {
    x *= 2;
}
```

Vector remains unchanged.

Why?

> `x` is a copy

Memory pictures:

```
vector: [1][2][3]

iteration:
x = copy of element
```

#### 2. Reference


```cpp
for (auto& x : v)
```

`x` refers to the real element.

Example:

```cpp
for (auto& x : v) {
    x *= 2;
}
```

Now the vector changes.

```
[1,2,3] → [2,4,6]
```

Memory picture:

```
vector: [1][2][3]

x → reference to element
```

#### 3. Const Reference

Very common pattern.

```cpp
for (const auto& x : v)
```

Meaning:

- reference
- no copying
- read-only

Example:

```cpp
for (const auto& x : v) {
    std::cout << x;
}
```

This is usually the **best default** when only reading data.

---

## When to use each form

| Pattern | Meaning | Use case |
|---------|---------|----------|
| `auto x` | copy | small values |
| `auto& x` | reference | modifying elements |
| `const auto& x` | read-only reference | large objects |

---

## Example with `std::string`

```cpp
std::string s = "hello";

for (char c : s) {
    std::cout << c;
}
```

Output:

```
h e l l o
```

---

## Modifying Characters

```cpp
for (char& c : s) {
    c = std::toupper(c);
}
```

Result:

```
HELLO
```

## Works with many containers

Range-based loops work with:

```
std::vector
std::string
std::array
std::map
std::set
custom containers
```

Example:

```cpp
std::vector<int> v = {1,2,3};

for (const auto& x : v) {
    std::cout << x;
}
```

---

## How it works internally

The loop:

```cpp
for (auto x : v)
```

is roughly equivalent to:

```cpp
for (auto it = v.begin(); it != v.end(); ++it) {
    auto x = *it;
}
```

Meaning:

```
begin() → iterator to first element
end()   → iterator past last element
```

This uses **iterators**, which are central to the C++ STL.

---

## Why it matters

Range-based loops are;

- shorter
- safer
- less error-prone
- more readable

They remove common bugs such as:

- off-by-one errors
- invalid indexing
- incorrect loop bounds

---

## Very common pattern

We will constantly see this in C++ code:

```cpp
for (const auto& item : container)
```

Meaning:

- iterate without copying
- read-only
- safe

This is one of the **most idiomatic patterns in modern C++**.

---

## Connect to C knowledge

C loop:

```c
for (int i = 0; i < n; i++) {
    process(arr[i]);
}
```

Modern C++:

```cpp
for (const auto& x : v) {
    process(x);
}
```

Cleaner and safer.

---

## Takeaway

> - Range-based loops simplify iteration.   
> - `auto` lets the compiler deduces types.  
> - `auto&` allows modification of elements.  
> - `const auto&` avoids copying and prevents modification.  
> - Internally they use iterators.
