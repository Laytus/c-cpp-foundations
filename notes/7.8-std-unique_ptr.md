# Module 7.8 – `std::unique_ptr`

### Learning Goals

- Understand **C++ ownership semantics**
- Learn what **`std::unique_ptr`** is
- Understand how it replaces **manual new / delete**
- Learn **move-only ownership**
- Understand how RAII works with dynamic memory
- Learn how to safely transfer ownership

---

## The Problem in C

In C, heap memory must be managed manually.

Example:

```c
int* p = malloc(sizeof(int));

*p = 10;

free(p);
```

Problems:

- memory leaks
- double free
- use-after-free
- unclear ownership

Large programs struggle with this.

---

## The C++ Idea: Ownership Types

Modern C++ expresses **ownerhsip explicitly**.

The are three main ownership models:

| Type | Meaning |
|------|---------|
| `std::unique_ptr` | single owner |
| `std::shared_ptr` | shared ownership |
| raw pointer | non-owning reference |

We start with the **most important one**:

> `std::unique_ptr`

---

## What is `std::unique_ptr`

A **smart pointer that owns exactly one object**.

Example:

```cpp
#include <memory>

std::unique_ptr<int> p = std::make_unique<int>(10);
```

Conceptually:

```
unique_ptr
   |
   V
  heap object
```

When the `unique_ptr` is destroyed:

> delete automatically runs

No manual `delete`.

---

## Basic Example

```cpp
#include <memory>
#include <iostream>

int main() {
    auto p = std::make_unique<int>(42);

    std::cout << *p << "\n";
}
```

Output:

```
42
```

When `main()` exists:

> `unique_ptr` destructor → delete

Memory is released automatically.

---

## Why `make_unique`?

Avoid writing:

```cpp
std::unique_ptr<int> p (new int(42));
```

Instead use:

```cpp
auto p = std::make_unique<int>(42);
```

Reasons:

- safer
- cleaner
- exception-safe

Modern C++ almost always uses **`make_unique`**.

---

## Dereferencing

Just like a normal pointer.

```cpp
*p
```

Example:

```cpp
auto p = std::make_unique<int>(5);

std::cout << *p;
```

Output:

```
5
```

---

## Accessing Members

If the pointer owns an object:

```cpp
struct Point {
    int x;
    int y;
}
```

Example:

```cpp
auto p = std::make_unique<Point>();

p->x = 10;
p->y = 20;
```

Just like a normal pointer.

---

## The Key Rule: Unique Ownership

A `unique_ptr` **cannot be copied**.

Example:

```cpp
auto p1 = std::make_unique<int>(5);
auto p2 = p1;
```

Error because:

```
two owners would exist
```

This is forbidden.

---

## Moving Ownership

Ownership can be **transferred**.

Example:

```cpp
auto p1 = std::make_unique<int>(10);

auto p2 = std::move(p1);
```

Now:

- `p1` → `NULL`
- `p2` → owns the object

Memory diagram:

Before move

```
p1 → object
p2 → empty
```

After `move`

```
p1 → null
p2 → object
```

---

## Why this matters

The compiler now enforces ownership rules.

Example mistakes prevented:

- double free
- accidential sharing
- unclear ownership

This is **huge for large systems**.

---

## Example function ownership transfer

```cpp
std::unique_ptr<int> create_value () {
    return std::make_unique<int>(42);
}
```

Usage:

```cpp
auto p = create_value();
```

Ownserhip moves automatically.

---

## Passing `unique_ptr` to functions

#### Transfer ownership

```cpp
void process(std::unique_ptr<Data> d);
```

Call:

```cpp
process(std::move(ptr));
```

Ownership moves into the function.

#### Borrow without ownership

```cpp
void process(const Data* d);
```

or

```cpp
void process(const Data& d);
```

The function does **not take ownership**.

---

## Arrays with `unique_ptr`

Example:

```cpp
auto arr = std::make_unique<int[]>(100);
```

Now we have:

```
heap array of 100 ints
```

Access:

```cpp
arr[5] = 42;
```

---

## Connection to C knowledge

C version:

```c
int* p = malloc(sizeof(int));

*p = 10;

free(p);
```

Modern C++ version:

```cpp
auto p = std::make_unique<int>(10);
```

Memory automatically freed when scope ends.

This is **RAII applied to heap memory**.

---

## When to use `unique_ptr`

We use it when:

- an object has a single clear owner

Examples:

- tree nodes
- resource handles
- heap objects
- file handles
- buffers

This covers **most real C++ code**.

---

## Mental Model

Think of `unique_ptr` as:

- owning pointer
- with automatic destruction
- and enforced single ownership

---

## Takeaway

`std::unique_ptr`:
> - expresses **exclusive ownership**.  
> - automatically deletes object.  
> - prevents accidental sharing.  
> - uses **move semantics** for ownership transfer.  
> - replaces many manual `new`/`delete` patterns.
